试写分两轮：

1. **第一轮，提示词只要求保留标签。** 模型会把材料里没有的内容补成填充句，例如 "from around the world"、"register early"，一篇 A 的 6 句中有 2 句不含标签。B 读 A 时逐字照抄 A，只在末尾加一句自己的事实。
2. **第二轮，加入"每句至少一个标签""用自己的话"后**（即 §4.1 的提示词），3 组共 9 篇：标签全部保留，无多余标签，无数字；37 句中只有 1 句不含标签。B 与来源的 3-gram Jaccard 为 0.08/0.16/0.24，B 与另一篇独立报道为 0.08/0.09/0.13，A 与 C 为 0.18/0.06/0.17。B 平均只比独立报道略接近自己的来源（0.16 对 0.10），而且第 1 组里 A 与 C 的重合（0.18）反而高于 B 与来源（0.08），因为 A、C 读的是同一张卡。

## 1. 总流程

```text
Phase 0  我写一条短新闻，抽成 <标签> 与事实卡（其中一行只给 B）
Phase 1  我为每个标签写 Truth 值和 Rumor 值
Phase 2  27B 读事实卡（只见标签、不见值）→ A、C（同一提示词，只换种子）
Phase 3  27B 读 A 或 C 的带标签原文 + B 专属那一行 → B_A、B_C（同一提示词）
         Duplicate 与 Rumor 两个分支各生成一套 A、C、B_A、B_C
Phase 4  分支内填值（Duplicate 全填 Truth；Rumor 把来源与 B 的部分标签填成 Rumor）
         → 组装 Set A / Set B / Set C，三通道全排列
Phase 5  按标签的字符位置逐 token 标注 0/1
```

生成全程不出现具体值，27B 没有机会改写数字。所有标签都由程序根据标签身份给出，不依赖文本相似度。

## 2. Phase 0：事件与标签（由我执行）

### 2.1 每个事件的产物

```json
{"event_id": "E0001", "domain": "academic conference", "tense": "future",
 "seed_text": "ACL 2027 will be held in Kyoto, Japan, in July. ...",
 "card": ["<Conference> <Year> will be held in <City>, <Country>, in <Month>.",
          "<Person_A> of <Affiliation_A> will give the opening keynote.",
          "Organisers expect <Attendees> participants."],
 "b_only": ["The conference is sponsored by <Sponsor>."],
 "tags": {"<City>": {"type": "city", "group": "place", "truth": "Kyoto", "rumor": "Busan"}, "...": {}}}
```

- `card`：A、C 读的事实卡，3–5 行。
- `b_only`：只给 B 的 1 行，作为 B 独立事实的依据；其中的标签不得出现在 `card` 里。
- 每个事件共 4–6 条事实（用户规定的范围）。
- `seed_text`：用一段话写出的随机虚构事件，只用于存档，不进入任何模型输入。

### 2.2 标签粒度（"适中"的具体规则）

| 规则 | 取值 | 理由 |
|---|---|---|
| 每个事件的标签总数 | 6–10 个（`card` 5–8 个，`b_only` 1–2 个） | 试写中 7–8 个标签全部保留；再多，27B 漏写的风险会上升 |
| 每行标签数 | 1–3 个，至少两行含 2 个以上 | 一行内有多个标签才构成"绑定"，不至于退化成单词匹配 |
| 必含类型 | 至少一个日期类、一个地点类、一个人物或机构类、一个数量类 | 保证每个事件都有可以被篡改的数值、时间和实体 |
| 标签名 | 语义类型 + 区分后缀，例如 `<Person_A>`、`<Person_B>`、`<Year>`、`<Attendees>`；名称内不用空格 | 名称要能让 27B 写出通顺的句子；同类标签用后缀区分 |
| 日期 | 拆成 `<Year>`、`<Month>`、`<Day>`，按需取用 | 采用用户建议；月份值写英文月名 |
| 值的形式 | 专名或数字，不以冠词开头，不含句号 | 填值后不破坏语法，也不影响分句 |
| 领域 | 从 8 类轮换：学术会议、企业、体育、公共政策、科研、灾害与事故、文化活动、医疗卫生；同一领域内的句式模板不得重复 | 吸取 v1.1 的教训：12 张卡完全相同时，数值会被模型记住 |

### 2.3 校验（确定性，由脚本执行）

- `card`、`b_only` 中的每个标签都在 `tags` 中有定义；`tags` 中的每个标签至少出现一次；
- `b_only` 与 `card` 的标签集合不相交；
- 标签总数、每行标签数、必含类型满足 §2.2；
- 卡片文字不含数字，所有数值都在标签里。

### 2.4 规模与执行方式

试点 20 个事件，正式 400 个。我按每批 20 个写成 JSON，每批写完先跑校验。400 个事件约需 25 万输出 token，分多轮完成。

## 3. Phase 1：Truth 与 Rumor 值（由我执行）

| 规则 | 说明 |
|---|---|
| 同类型、同格式 | 城市换城市，年份换年份，金额换同单位金额 |
| 与 Truth 不同，同样可信 | 数量类取 Truth 的 0.5–2 倍；人名、机构名同样是虚构但合理的 |
| 关联组一起替换 | 城市与国家、年月日、人物与所属机构各为一组。替换后组内仍然一致，例如 Kyoto/Japan 换成 Busan/South Korea，而不是 Shizuoka/Ukraine |
| 时态一致 | `tense` 为 future 的事件，Rumor 年份也在将来；不出现"将于 1996 年举行" |
| 不与其他标签撞值 | Rumor 值不等于本事件任何标签的 Truth 值 |

Truth 本身也是虚构的。Truth 与 Rumor 只是本事件指定的两套版本，都不能靠世界知识判断真假，这一点符合 AGENTS.md"不假设模型能识别事实真伪"的约定。

这里与用户的例子有一处不同：例子中的 Rumor 是 Shizuoka/Ukraine、1996 年。若 Rumor 值组内矛盾或时态不合，预训练编码器凭世界知识就能认出它（静冈不在乌克兰，2027 年的会议不会在 1996 年举行），模型就不必读池内关系。本计划要求关联组一起替换、保持一致（见 Q6）。

## 4. Phase 2：独立报道 A、C

### 4.1 共用提示词（A、C、B 完全相同）

```text
You are a news reporter. Write a news report of 50-90 words based only on the material below.

Words in angle brackets, such as <City>, stand for details you are not shown. Copy each one exactly, brackets included. Never replace them with names or numbers, never create new ones, and write no digits.
Every sentence must contain at least one bracketed word. Use every bracketed word in the material at least once. Do not add any fact that is not in the material. Write in your own words; do not copy sentences from the material.

MATERIAL
- <每行一条>

Return only the report.
```

- A、C 的 MATERIAL 是 `card`，行序相同。
- 参数：`temperature 0.8`，`max_tokens 400`，`chat_template_kwargs.enable_thinking false`。A 与 C 只有 `seed` 不同。
- "Write in your own words" 是决定难度的主要开关。去掉它，B 会逐字照抄来源；保留它，B 与来源的重合只略高于与独立报道的重合（§0）。因为提示词必须相同，这句话对 A、C 同样生效；对 A、C 而言，它只是让事实卡的短句被改写成报道句。

### 4.2 审计（确定性）与重试

每篇必须同时满足：

1. 只出现 MATERIAL 中的标签；MATERIAL 中的每个标签至少出现一次；
2. 不含数字；
3. 每句至少含一个标签（按 `.!?` 后接空白切句）；
4. 40–110 词（目标 50–90，留余量；超过 160 个 MPNet token 的在 §6.1 丢弃）；
5. 不含 MATERIAL 字样、项目符号或 markdown。

不通过就**只换种子**重写，最多 6 次。不在提示词后附加纠错说明，否则 A、B、C 的提示词就不再相同。6 次仍失败，则丢弃该事件在该分支中的全部文档，并记录原因。

## 5. Phase 3：派生 B

### 5.1 B 的输入

- MATERIAL = 来源文档（A 或 C）的带标签原文，按句切成多行、保持原句序；再把 `b_only` 的行随机插入其中。之所以随机插入，是为了避免"B 的独有事实总在最后一句"。
- 提示词、参数与 §4.1 相同，只换种子。
- 每个事件、每个分支生成两篇：`B_A`（读 A）与 `B_C`（读 C）。

审计在 §4.2 之上增加两条：B 的标签 ⊆ 来源标签 ∪ `b_only` 标签；`b_only` 的标签全部出现。

### 5.2 Duplicate 与 Rumor 两个分支

两个分支各自用不同种子生成一套 `A, C, B_A, B_C`，每个事件每个分支 4 篇。

27B 在生成时看不到任何值，所以两个分支生成的文本分布完全相同，区别只在 Phase 4 的填值：

- **Duplicate**：所有标签都填 Truth。
- **Rumor**：来源文档中 1–2 个关联组的标签填 Rumor；B 中转自来源的标签继承来源的值，因此 B 也带上了 Rumor；B 的独有事实、以及另一篇独立报道，都填 Truth。

用户原文说"让 B 读到 Ukraine"。本计划不让 B 读具体值，而是让 B 读标签，到填值时再继承来源的 Rumor 值。这样做的效果与"B 读到错误内容后照着写"相同，又保持了 27B 对值全盲，避免小模型改动数字。这一点列为待确认事项 Q3。

## 6. Phase 4：填值与组装

### 6.1 填值按数据对进行

同一篇文档在不同数据对里可能填不同的值。例如 Rumor 分支中，A 在 `(A, B_A, C)` 里是来源，带 Rumor 值；在 `(A, C, B_C)` 里是旁证，带 Truth 值。因此填值发生在组装每个数据对时，并记录每个值的字符区间与版本（truth/rumor），供 Phase 5 使用。

填值后的确定性修正与检查：

- 冠词：值前的 `a/an` 按值的首音修正，修正在计算区间之前完成；
- 检查每个值都落在句内，没有破坏分句；
- 用训练所用的 MPNet 分词器检查每篇长度不超过 160 token（ABC 结构是 `[batch, 3, 160]`）；超长的文档整篇丢弃。

### 6.2 三个 Set（每个分支各一套）

| Set | 三个通道 | 每事件数据对数 |
|---|---|---:|
| A | `(A, B_A, C)` 与 `(A, C, B_C)`，各 6 种排列 | 12 |
| B | `(A, B_A, X)` 与 `(C, B_C, X)`，X 为其他事件的一篇 A 或 C，各 6 种排列 | 12 |
| C | `(X1, B, X2)`，B 取 `B_A` 与 `B_C` 各一次，X1、X2 为其他事件的 A 或 C（允许来自同一事件），各 6 种排列 | 12 |

- 每个分支每事件 36 对，两个分支 72 对；Duplicate/Rumor × Set A/B/C 六类按构造就是 1:1:1:1:1:1。
- 规模：试点 20 个事件得到 1,440 对；正式 400 个事件得到 28,800 对。
- Set B、C 中的 X 只从同一分支、同一数据划分内抽取，不跨训练、开发、测试集。X 一律填 Truth。
- Rumor 分支中，B 在 Set C 里沿用它在 Set A 中继承的 Rumor 值。

### 6.3 数据划分

按事件划分 70/15/15。同一事件的全部排列、两个来源选择、两个分支都在同一个集合里。这符合 AGENTS.md"按事件家族隔离，不把同一 ABC 的不同排列当独立事件"的规定。有效样本量按事件数计，不按数据对数计。

## 7. Phase 5：逐 token 标注

### 7.1 标签规则

| Set | 文档 | 标签 |
|---|---|---|
| A、B | 来源（B 读过的那篇 A 或 C） | 0 |
| A | 另一篇独立报道（C 或 A） | 0 |
| A、B | B 中转自来源的标签 | 1 |
| A、B | B 中的 `b_only` 标签 | 0 |
| B | 其他事件的文档 X | 0 |
| C | 全部标签 | 0（见待确认事项 Q1） |

- 标签值所覆盖的 token 记为 0 或 1；标签以外的 token 记为忽略（-100），不进入损失。用户只规定了标签 token 的标注，这里按"只标标签"执行。
- 同一标签在一篇中出现多次时，每处都打相同的标签。
- token 是否属于某个值，按分词器的字符偏移与 §6.1 记录的区间判断，不做字符串搜索。

### 7.2 产物格式

`pairs.jsonl`，每行一个数据对：

```json
{"pair_id": "...", "branch": "rumor", "set": "A", "split": "train", "perm": "BCA",
 "channels": [{"doc_id": "E0007.dup.B_A", "role": "B", "event_id": "E0007", "text": "...",
               "spans": [{"start": 0, "end": 3, "tag": "<Conference>", "label": 1,
                          "version": "rumor", "from": "source"}]}]}
```

另存按 MPNet 分词后的 `token_labels.npz`（`[N, 3, 160]`），以及事件表 `events.jsonl`（Phase 0/1 的全部内容）。

## 8. 风险与需要实测的问题

### 8.1 事实集合结构直接暴露角色

按 Phase 2–3 的构造，A 和 C 读同一张卡，事实集合完全相同；只有 B 多出 `b_only`。填值之后，可以用一条不读措辞的规则解出 Set A、B 的全部标签：

> 某篇文档含有池中其他文档没有的值，它就是 B；B 中与其他文档共有的值标 1，其余全标 0。

这条规则只看"哪些值在哪几篇里出现"。模型学到它，就不需要判断传抄。

可选的修改（需要你决定，见 Q4）：

- A、C 各加一条只属于自己的事实（`a_only`、`c_only`），B 转述来源时随机丢掉一行。这样每篇都有独有内容，事实集合不再能指认 B。
- 代价：A 与 B 之间谁抄谁，只能靠措辞判断。试写中 B 与来源的 3-gram 重合平均只比与独立报道高约 0.06，3 组中有 1 组持平，这个任务可能接近不可识别。

建议先按你的原设计跑试点，实测这条规则的得分再决定。

### 8.2 Rumor 在文本中能否被识别

Truth 与 Rumor 都是虚构值，文本本身没有判断哪个是真的依据（AGENTS.md：不假设模型能识别事实真伪）。在 Rumor 分支里：

| Set | 池内能看到的 |
|---|---|
| A | 来源 A（Rumor）、B（继承 Rumor）、独立报道 C（Truth）。能看到 A、B 与 C 在同一标签上冲突，但看不出哪一方是 Rumor |
| B | 来源与 B 一致，X 来自其他事件，没有任何冲突 |
| C | B 带 Rumor，X 来自其他事件，没有任何冲突 |

所以"核实/编造"作为逐 token 标签，只在 Rumor·Set A 中以"与另一篇独立报道冲突"的形式存在，其他四类都不可识别。本计划在每个区间记录 `version`（truth/rumor），另外计算一个 `conflict` 字段（同一标签在池中另有不同值）。是否把哪一个作为训练目标，见 Q2。

Rumor·Set A 本身有研究价值：池中 Rumor 值有两篇支持（来源 A 与转抄它的 B），Truth 值只有一篇（C）。按篇计票，Rumor 以 2:1 胜出；把 B 识别为传抄并折算掉之后，是 1:1。这正是 WFW 主线研究的重复偏置，可以直接用翻转率评测：去掉或保留 B 时，下游判断是否改变。

### 8.3 其他

| 风险 | 处理 |
|---|---|
| 27B 漏写标签或改写标签名 | §4.2 审计，换种子重试；统计每类标签的丢失率，丢失率高的类型在 Phase 0 中少用 |
| "用自己的话"让 B 的措辞继承过弱，任务不可识别 | 试点报告 B–来源与 B–独立报道的重合差；必要时在三种提示词措辞之间选一种，三类文档同步更换 |
| 我生成的事件多样性不足 | 每批统计句式模板、值的重复率；同领域内模板不得重复 |
| 冠词、单复数填值后不通顺 | §6.1 的冠词修正；试点人工抽查 10 个事件 |
| 端点单槽位，并发无加速 | 串行调用。估算 400 个事件 × 8 篇 × 约 1.3 倍重试 × 2.4 秒 ≈ 2.8 小时 |
