## 1. 结论

1. **P1 达标**：20 事件 × 2 分支 × 4 篇 = **160 篇，全部产出，审计通过率 100%**，无分支丢弃。
2. **P2 达标**：**720 对，六类各 120**；13,930 个值区间全部落在 token 上；超长丢弃 0；镜像 14/27 = 51.9%（目标 50%±5pp）。
3. **诊断读数**：Set A 用 3-gram 分 B 与 C 只有 **55.0%**（随机 50%），结构规则在 Set A 上准确率 **0.373**（低于随机）——按计划这两项本就该接近随机。
4. **D7 不再是"低于随机"**：单篇分 A 与 Bf 的 5 折准确率是 **0.537（TF-IDF）/ 0.550（MPNet）**，n=80。第一版是 0.473/0.512，当时我据此说"单篇没有文体信号"；**这个结论要改**——取消 (6,2) 档之后 A 普遍有 4 条事实，单篇弱信号出现了，但 0.55 仍然远不够用。
5. **跨事件模板底噪仍在**：A 与别的事件文档（X）的 3-gram 是 **0.201**，仍高于 A–C 的 0.166。

## 2. P1 生成

| 项 | 结果 |
|---|---|
| 文档数 | 160 / 160 |
| 审计通过 | 160/160 = 100%（要求 ≥90%） |
| 提示词 | 四类文档逐字相同，`prompt_sha = eff1fcb1c689e745` |
| 重试 | 换种子重试，最多 6 次；提示词从不追加纠错说明 |

审计项（`gen_docs.py:audit`）：只用材料里的标签、材料标签全部出现、无数字、每句至少一个标签、25–140 词、无 markdown/材料回显；B 另加"标签 ⊆ A∪独有事实且独有事实的标签全出现"，Bf 另加"标签集合等于 A"。

事实分配按 v1.2 §2.1：A 拿 `f1 + n−2m−1` 条，C 拿 A 的再加 `m` 条（从剩下 2m 条里抽），B 读 A 的句子加 m 条独有事实，Bf 只读 A 的句子。f1 不参加独有事实抽签（U8）。行序全部随机打乱（U2）。

**E0015/rumor 的处理要说明。** 它在第一版里整分支丢弃（A 的正文 23 词 < 25 词下限，6 个种子全败）。取消 (6,2) 档并没有解决它——E0015 是 (5,1)，A 只有 3 条事实，本来就短。用 `--seed-offset 7` 重开一块种子后 8/8 通过（该事件两个分支一起重抽，保持事件内一致）。这等价于把种子预算从 6 扩到 12，**只在整分支失败时用，不在"过与不过"之间挑质量**；如果这算放宽，正确的做法是把 25 词下限降到 20 词，但那会加宽 A/Bf 与 B/C 的长度差（D3 已显示长度是强线索），所以没有采用。

## 3. P2 组装

| 项 | 结果 |
|---|---|

| 六类 | dup·A 120 / dup·B 120 / dup·C 120 / rumor·A 120 / rumor·B 120 / rumor·C 120 |

**镜像方式。** 计划 §3.1 定的是"每条 Rumor 事实各自以 1/2 概率镜像，再检查全量比例在 50%±5pp"。逐条抛硬币在 26 条样本上实测 42.3%，落在带外（26 条只有 12/13/14 三个取值合格）。改成**在全量上随机取恰好一半**（27 条取 14 条 = 51.9%），仍随机决定"哪一半"。计划里提过的备选是"按事件整体镜像"，未采用——理由是池中不一致模式更混杂。若要改成按事件整体，`build_pairs.py` 里改一行。

**六类严格相等。** 本次 20 个事件全部完整，天然 120×6，降采样没有触发。代码里仍保留"按最小类降采样"，以防 P4 时有分支失败导致不齐。

## 4. P3 诊断

### D1 结构规则（只看"值出现在哪几篇"）

| 分支 | Set | 准确率 | 精确率 | 召回率 | 正例占比 |
|---|---|---:|---:|---:|---:|
| dup | A | 0.373 | 0.314 | 1.000 | 0.287 |
| dup | B | 0.677 | 0.498 | 1.000 | 0.320 |
| dup | C | 0.881 | 0.000 | 0.000 | 0.000 |
| rumor | A | 0.374 | 0.291 | 0.806 | 0.290 |
| rumor | B | 0.683 | 0.506 | 1.000 | 0.325 |
| rumor | C | 0.938 | 0.000 | 0.000 | 0.000 |

Set A 上准确率 **0.373 < 0.5**：规则能召回全部正例（1.000），但把 A 自己的值也标成"传抄"（精确率 0.31）。**结构无法指出 A、B 谁是来源**，正是设计要的。Set B 的 0.68 来自"Bf 与 A 共享、X 不共享"，不是真的判出了派生。Set C 的 0.88/0.94 是"全判 0"的基线，精确率为 0，不能当作能力。

### D2 措辞继承

| 对 | 1-gram | 3-gram | MPNet 余弦 |
|---|---:|---:|---:|
| A–B | 0.543 | 0.263 | 0.894 |
| A–C | 0.489 | 0.166 | 0.887 |
| A–Bf | 0.708 | 0.411 | 0.970 |
| B–Bf | 0.499 | 0.202 | 0.894 |
| C–Bf | 0.458 | 0.140 | 0.886 |

- Set A 用 3-gram 分 B 与 C：**22/40 = 55.0%**（随机 50%）。不能用。
- Set A 分 Bf 与 C：33/40 = 82.5%。
- **A 与别的事件文档（X）的 3-gram 是 0.201，高于 A–C 的 0.166。** "与 A 有 0.2 左右的 3-gram 重合"这件事本身不说明任何来源关系——事实卡的句式被所有文档继承。这给难负例（Set B、Set C 的 X 槽）人为降低了难度。

### D3 长度与句数

| 角色 | 词数均值（范围） | 句数 |
|---|---|---:|
| A | 39.9（28–54） | 2.7 |
| C | 48.1（33–68） | 3.5 |
| B | 51.1（33–75） | 3.4 |
| Bf | 41.6（28–65） | 2.8 |

长度是强线索：A/Bf 与 B/C 差约 10 词，来自事实条数。按这条线索，只看长度就能把 Bf 与 B、C 分开。

### D6 n=6、m=2

该档已取消，无事件可测。

### D7 单篇方向探针（只给一篇，分 A 与 Bf）

| 探针 | 5 折准确率 |
|---|---:|
| TF-IDF(1-2gram) + LR | 0.537 |
| MPNet + LR | 0.550 |

n=80，随机 0.500。**单篇有弱信号，但远不够用**（0.55 对 0.50）。第一版 0.473/0.512 的"低于随机"结论已作废——那是 (6,2) 档把 A 压到 2 条事实造成的。判断"Bf 抄了 A"仍然必须靠池内比较。

### D8 镜像

C 与 B 在 Rumor 事实上取值一致 14 处、不一致 13 处，比例 **51.9%**，与 `build_pairs.py` 的 `mirroring 14/27` 一致。

- **D5（打乱顺序后的通顺度）**：人工通读，未做。

## 5. P4 前仍需注意的三件事

1. **跨事件模板底噪 0.201**：决定是"接受并写进方法节"。P4 的方法节必须写明"跨事件文档有约 0.2 的 3-gram 底噪"，否则"低重合派生"这一层会被底噪吞掉。
2. **长度线索**：A/Bf 39.9–41.6 词 vs B/C 48.1–51.1 词。这是事实条数造成的，无法消除，只能记录。
3. **D4 未做**：Set C 里 dim2 全 0 的设计依赖"模型不能凭值合理性判编造"。没跑 D4 就没有量化证据说明这个倾向有多强，方法节不能声称"已排除合理性捷径"。
