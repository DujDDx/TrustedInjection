## 2. 标签定义

每个事件生成三篇文档。按用户的命名，A、C 指"来源"和"旁证"两个角色，不指固定的文档：

| 角色 | 本计划记号 | 读什么 | 事实条数 |
|---|---|---|---:|
| 来源（被 B 读的那篇独立报道） | S | 事实卡中 n−2m 条 | n−2m |
| 旁证（另一篇独立报道） | O | 事实卡中 n−m 条 | n−m |
| 派生 | B | S 的带标签原文 + m 条 B 自有事实 | n−m |

逐 token 的两维标签，只标占位符值所在的 token：

| 维度 | 取值 | 规则 |
|---|---|---|
| dim1 传抄 | 0 = 独立 | S、O 中的全部值；B 自有事实中的值；Set B 中的外部文档；Set C 中的全部值 |
| | 1 = 传抄 | 在池中能找到来源的 B 转述值，包括 Rumor 分支中被换成 Rumor 的转述值（句子是转述来的，只是值被改了）。只在 Set A、Set B 中出现 |
| dim2 编造 | 0 = 核实 | S、O 中的全部值；B 自有事实中的值；B 转述值中与来源一致的 |
| | 1 = 编造 | B 的转述值与池中来源的值不同。只在 Rumor 分支的 Set A、Set B 中出现 |
| | 不参与 | Set C 中 B 的转述值来源不在池中，编造与否无法判定，dim2 记 -100（§8.2） |

两条规则的含义：

- **B 是"传抄"，以它在池中能否找到来源为准，而不是以它生成时读了什么为准。** Set C 中 B 的来源不在池中，它在这个池里就是独立的。这与 AGENTS.md 中"移除 A 后，B 重新获得代表资格"一致。
- **编造只在 B 上判定，A、C 都标核实。** 判定依据是"B 抄了 S，而且 B 与 S 的事实不同"，只用到池内关系，不依赖世界知识。

Set C 中 B 的转述值，dim1 标 0（独立），dim2 不参与。§9 的 D6 会单独报告这部分是否仍能从文本识别。

## 3. 总流程

```text
Phase 0  我写短新闻，抽成 <标签> 与 n 条事实（其中 m 条只给 B）
Phase 1  我为每个标签写 Truth 值与 Rumor 值
Phase 2  事实分配：S ← n−2m 条，O ← n−m 条，两组各自随机抽取
         27B 读事实卡（只见标签）→ S、O（同一提示词，只换种子）
Phase 3  27B 读 S 的带标签原文 + m 条 B 自有事实 → B（同一提示词）
         Duplicate、Rumor 两个分支各自独立生成一套 (S, O, B)
Phase 4  填值：S、O、B 自有事实填 Truth；B 的转述值在 Duplicate 填 Truth，在 Rumor 填 Rumor
         组装 Set A / B / C，三通道 6 种排列
Phase 5  按字符区间逐 token 标注 dim1、dim2
```

27B 在整个生成过程中看不到任何具体值，只看到标签。

## 4. Phase 0：事件与标签（由我执行）

### 4.1 每个事件的产物

```json
{"event_id": "E0001", "domain": "academic conference",
 "seed_text": "ACL 2027 will be held in Kyoto, Japan, in July. ...",
 "facts": [
   {"id": "f1", "text": "<Conference> <Year> will be held in <City>, <Country>, in <Month>.", "b_only": false},
   {"id": "f2", "text": "<Person_A>, a professor at <Affiliation_A>, will give the opening keynote.", "b_only": false},
   {"id": "f3", "text": "The organisers expect <Attendees> participants.", "b_only": false},
   {"id": "f4", "text": "The registration fee has been set at <Fee>.", "b_only": false},
   {"id": "f5", "text": "The conference is sponsored by <Sponsor>.", "b_only": true}],
 "tags": {"<City>": {"type": "city", "truth": "Kyoto", "rumor": "Busan"}}}
```

- `seed_text` 只用于存档，不进入任何模型输入。
- 每条事实文字中的数值、名称一律写成标签，事实文字本身不含数字。

### 4.2 规模与粒度

| 项 | 取值 |
|---|---|
| 事实条数 | n = 5 或 6；m = 1（n = 6 时允许 m = 2） |
| 对应条数 | n=5, m=1：S 3、O 4、B 4；n=6, m=1：S 4、O 5、B 5；n=6, m=2：S 2、O 4、B 4 |
| 每条事实的标签数 | 1–3 个；每个事件至少两条事实含 2 个以上标签 |
| 每个事件的标签总数 | 6–11 个 |
| 必含类型 | 至少一个日期类、一个地点类、一个人物或机构类、一个数量类 |
| 标签名 | 语义类型 + 区分后缀，例如 `<Person_A>`、`<Attendees>`；名称内不用空格 |
| 标签归属 | 每个标签只属于一条事实。不同事实不共用标签，这样每个值所在的事实是唯一的，dim1 可以按事实判定 |
| 日期 | 拆成 `<Year>`、`<Month>`、`<Day>`，按需取用；月份值写英文月名 |
| 值的形式 | 专名或数字，不以冠词开头，不含句号 |
| 领域 | 8 类轮换：学术会议、企业、体育、公共政策、科研、灾害与事故、文化活动、医疗卫生；同一领域内句式不得重复 |

n=6、m=2 时 S 只有 2 条事实。试写只测过 3–4 条，这一档在 §9 的 D7 单独看文本质量。

### 4.3 校验（确定性，由脚本执行）

- 每个标签在 `tags` 中都有定义，`tags` 中的每个标签恰好出现在一条事实里；
- 事实条数、b_only 条数、标签数、必含类型满足 §4.2；
- 事实文字不含数字；
- Truth 与 Rumor 值不同。

### 4.4 执行方式

我按每批 20 个事件写成 JSON，写完先跑校验。试点 20 个事件，正式 400 个，分多轮完成。

## 5. Phase 1：Truth 与 Rumor 值（由我执行）

- 每个标签一个 Truth 值、一个 Rumor 值，两者不同，类型相同（城市换城市，年份换年份）。
- 按用户答复，Rumor 不要求与同一事件的其他值保持一致，也不要求时态合理，可以出现 Shizuoka/Ukraine、1996 年这类组合。
- Truth 本身也是虚构的。

在文本上能否只凭世界知识认出 Rumor，由 §9 的 D5 测量。

## 6. Phase 2–3：生成 S、O、B

### 6.1 共用提示词（S、O、B 完全相同）

```text
You are a news reporter. Write a short news report based only on the material below.

Words in angle brackets, such as <City>, stand for details you are not shown. Copy each one exactly, brackets included. Never replace them with names or numbers, never create new ones, and write no digits.
Every sentence must contain at least one bracketed word. Use every bracketed word in the material at least once. Do not add any fact that is not in the material. Write in your own words; do not copy sentences from the material.

MATERIAL
- <每行一条>

Return only the report.
```

- 参数：`temperature 0.8`，`max_tokens 500`，`chat_template_kwargs.enable_thinking false`。三类文档只有 `seed` 和 MATERIAL 不同。
- 提示词不限字数。v1.0 限定 50–90 词，S 的事实比 O、B 少一条，限字数会让 S 写得更啰嗦，长度分布反而失真。试写中 S 平均 38 词，O、B 平均 44、43 词，差异来自事实条数。这是否构成长度线索，由 §9 的 D3 测量。
- "Write in your own words" 是决定措辞继承强弱的主要开关，三类文档同时生效。

### 6.2 事实分配（用户 Q4 方案）

- 共有事实 = 全部事实中去掉 m 条 b_only，共 n−m 条。
- S ← 从共有事实中随机抽 n−2m 条；O ← n−m 条共有事实。共有事实一共只有 n−m 条，所以 O 实际总是读全部共有事实，两组的随机抽取只对 S 起作用。
- O 覆盖 S 的全部事实，这一点很重要：如果 S 有一条 O 没有的事实，这条事实就只在 S 和 B 中出现，"只有两篇共有的值"会直接指出 B 抄了 S。
- B ← S 生成的带标签原文（按句切成多行，保持原句序）+ m 条 b_only 事实，b_only 随机插入其中。
- 两个分支（Duplicate、Rumor）各自重新抽取事实子集、各用不同种子，独立生成一套 (S, O, B)。

结果：S 有 n−2m 条事实，O 与 B 各有 n−m 条。在 Duplicate·Set A 中，"事实条数最多、而且含有别人没有的值"不再能指认 B：O 也含有 S 没有的事实（S 漏掉的 m 条共有事实），B 含有 b_only，两者各有 m 条别人没有的事实。

结构上仍能认出 S：它的事实全部被 B 和 O 包含，自己没有独有的值。这不构成捷径，因为 S 的值无论如何都标 0；要判断的是 B 与 O 中哪一篇抄了 S，这只能靠措辞。Set B 与 Rumor·Set A 中的结构捷径见 §12。

### 6.3 审计（确定性）与重试

每篇必须同时满足：

1. 只出现 MATERIAL 中的标签；MATERIAL 中的每个标签至少出现一次；
2. 不含数字；
3. 每句至少含一个标签（按 `.!?` 后接空白切句）。这条是用户的硬性要求："最终匹配到的句子必须包含至少一个 `<>` 标签"；
4. 25–140 词；
5. 不含 MATERIAL 字样、项目符号或 markdown。

B 另加：B 的标签 ⊆ S 的标签 ∪ b_only 的标签；b_only 的标签全部出现。

不通过就只换种子重写，最多 6 次，不在提示词后附加纠错说明，以保持三类文档的提示词完全相同。6 次仍失败，该事件在该分支整体丢弃并记录原因。

## 7. Phase 4：填值与组装

### 7.1 填值

| 文档 | Duplicate 分支 | Rumor 分支 |
|---|---|---|
| S、O | Truth | Truth |
| B 的 b_only 值 | Truth | Truth |
| B 的转述值 | Truth | 从 S 转述的事实中随机选 1–2 条，这些事实内的全部值填 Rumor；其余转述值填 Truth |

按用户答复，S、O 始终是真值，Rumor 只出现在 B 上。每篇文档的填值与它所在的数据对无关，因此每个分支每个事件只需填一次。

Rumor 分支中，B 的转述事实有 n−2m 条，按 §4.2 的取值是 2–4 条。转述事实为 2 条时替换 1 条，3–4 条时随机替换 1–2 条，保证 B 至少保留一条与 S 一致的转述。

填值后的修正与检查（确定性）：

- 冠词：值前的 `a/an` 按值的首音修正，修正在计算字符区间之前完成；
- 检查每个值都落在句内，没有破坏分句；
- 用 MPNet 分词器检查每篇不超过 160 token（ABC 结构 `[batch, 3, 160]`）；超长的文档整篇丢弃。

### 7.2 三个 Set（每个分支各一套）

| Set | 三个通道 | 每事件数据对数 |
|---|---|---:|
| A | (S, B, O) | 6（全部排列） |
| B | (S, B, X)，X 为其他事件的一篇 S 或 O | 6 |
| C | (X1, B, X2)，X1、X2 为其他事件的 S 或 O，允许来自同一事件，但不取同一篇 | 6 |

- 每个分支每事件 18 对，两个分支 36 对；Duplicate/Rumor × Set A/B/C 六类按构造为 1:1:1:1:1:1。
- 规模：试点 20 个事件 720 对，正式 400 个事件 14,400 对。
- X 从同一分支、同一数据划分中抽取，只用 S 或 O，不用 B，以免引入第二篇派生文档。
- 每个事件在 Set B、Set C 中各抽一次 X，6 个数据对是同一组三篇文档的 6 种排列，与 Set A 一致。
- Set C 中 X1、X2 来自同一事件时，池中就有两篇共享事实、彼此都是独立报道的文档，它们的标签全为 0。这是"同源但无派生"的难负例。
- v1.0 中 Set A 的"A、C 互换来源"（12 对）在本版不再需要：S 与 O 的事实条数不同，不能简单对调；两个分支已经各自独立重新生成一套。

### 7.3 数据划分

按事件划分 70/15/15。同一事件的两个分支、全部排列都在同一个集合里（AGENTS.md：按事件家族隔离，不把同一 ABC 的不同排列当作独立事件）。有效样本量按事件计。

## 8. Phase 5：逐 token 标注

### 8.1 标注对象

- 只标占位符值所在的 token。按分词器的字符偏移判断 token 是否落在 §7.1 记录的区间内，不做字符串搜索。
- 一个 token 与区间部分重叠时，也按区间内处理。
- 同一个值在一篇中出现多次，每处标相同的标签。

### 8.2 忽略方式

非标签 token 的 dim1、dim2 都记为 -100，PyTorch 的 `cross_entropy` 与 `binary_cross_entropy_with_logits` 按掩码跳过，不进入损失，也不进入指标分母。这是 token 分类任务的常规做法（Hugging Face 的 token classification 也用 -100 屏蔽子词和特殊 token）。

不采用 0.5 或 0.3 这类中性软标签，原因有两个：

- 二元交叉熵的目标设成 0.5，仍会产生梯度，把这些 token 的预测推向 0.5，等于给模型加了一个"非标签 token 要不确定"的额外任务；
- 这些 token 数量是标签 token 的数倍，会稀释标签 token 的梯度。

Set C 中 B 的转述值，dim2 也记 -100（§2）。

### 8.3 产物

- `events.jsonl`：Phase 0/1 的全部内容，以及两个分支的事实分配。
- `docs.jsonl`：每篇文档的带标签原文、填值后正文、每个值的字符区间、所属事实、来源（S 的哪个事实）、版本（truth/rumor）。
- `pairs.jsonl`：每行一个数据对，记录分支、Set、划分、排列，以及三个通道的 doc_id。
- `token_labels.npz`：`input_ids`、`attention_mask`、`dim1`、`dim2`，形状均为 `[N, 3, 160]`。

| D1 | 结构规则：只看"哪些事实、哪些值出现在哪几篇里"来指认 B 和标注 dim1，按"分支 × Set"分开报告 | 检验 §6.2 的事实分配是否消除了结构捷径。预计 Duplicate·Set A 已消除（B、O 结构对称）；Set B 可由包含关系解出，Rumor·Set A 可由多数一致解出（见 §12） |
| D2 | 值重合规则：B 中某个值在池中另一篇出现，就标 dim1=1 | Set A 中 B 的转述值同时出现在 S 和 O 中，这条规则只能指认共有，不能指认来源 |
| D3 | 长度、句数探针：区分 S、O、B 的角色 | S 少一条事实带来的长度差 |
| D4 | 措辞继承：B 与 S、B 与 O 的 3-gram Jaccard 与冻结 MPNet 余弦；能否据此从 S、O 中选出来源 | 任务难度，即 dim1 能否从文本识别 |
| D5 | 只看单个值所在的句子（不给池），区分 Rumor 值与 Truth 值：值本身的 TF-IDF、冻结 MPNet + 线性探针 | 不要求一致之后，Rumor 能否凭世界知识被认出 |
| D6 | Set C 中 B 的转述值：单篇文本能否区分它与 b_only 值 | 检查 Set C 的"全部独立"是否与文本信号冲突 |
| D7 | n=6、m=2 时 S 只有 2 条事实，文本质量与审计通过率 | 这一档能否保留 |

另外做人工抽查：读 10 个事件的全部文档，看填值后的语法和事实是否通顺。

## 12. 仍需你确认的两点

Set B 的池是 (S, B, X)。B 转述了 S 的全部事实，再加上 m 条自有事实，所以 S 的事实集合严格包含于 B。于是存在一条结构规则：

> 两篇共享事实时，事实更多、并且包含另一篇的那篇是派生；它与另一篇共有的值标 1。

这条规则不读措辞，就能解出 Set B 的全部 dim1 标签。Set A 不受影响，因为 B 与 O 事实条数相同、各有一条对方没有的事实，结构上无法区分。

可选的修改：B 只转述 S 的部分事实，随机丢掉一条，S 与 B 就不再是包含关系。代价是 B 的事实条数变为 n−m−1，又与 O 不同，Set A 会重新出现条数差。

另一条相关的结构规则出现在 Rumor·Set A。S 与 O 都是 Truth，在所有共有事实上一致，只有 B 在 1–2 条事实上与它们不同。于是"与另外两篇不一致的那篇是 B"可以直接指认 B，dim1 也随之解出，而 Rumor·Set A 占 Set A 数据的一半。这条规则正是你说的推理（X 抄了 Y，又与 Y 不同，X 就是编造），只是在本数据中，"与另外两篇都不同"本身就足以说明 X 是派生，不需要先判断传抄关系。按你的设定 A、C 始终是真值，这条规则无法通过构造消除。

我的默认做法：两处都不改，按原设计跑试点。D1 分别实测 Set B 被包含关系解出的比例、Rumor·Set A 被多数一致解出的比例，再由你决定。
