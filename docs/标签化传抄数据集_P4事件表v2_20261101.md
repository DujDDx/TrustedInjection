## 1. 为什么重做

旧表通过了当时的 `validate_events.py`，但有一个直接造成捷径的问题和几项不符合计划的地方：

| 问题 | 旧表 | 影响 |
|---|---|---|
| 错值方向 | 数量类错值 98% 小于真值，年份 91% 早于真值 | Rumor·Set A 中"数大的是来源"即可认出 A，U5 镜像失效；dim2 学成"数小的是编造"，违反 U7 |
| 句式重复 | 129 个句式跨事件重复（"The scheme costs <T>." 15 次） | 违反 v1.1 §4.2"同一领域内句式不得重复" |
| 领域 | 400 个自由标签，水务/铁路占 23.5% | 未按 v1.1 §4.2 的 8 类轮换 |
| 实体复用 | London 当真值 47 次，Network Rail 16 次 | 模型可记住"某值总是真值" |
| 同主体 | 27 组事件 f1 主体相同 | 同一故事重复 |
| 种子 | 机械拼接 | v1.1 §3 要求先写短新闻再抽事实 |

## 2. 校验器（`validate_events.py`）现在覆盖的计划条款

逐事件：

| 条款 | 检查 |
|---|---|
| v1.2 §4、11-01 决定 | 网格只允许 (5,1)、(6,1)；f1 含 agent/name/place 标签 |
| v1.1 §4.1 事实文字不含数值、名称 | 标签外无数字、**无数词**（two、half、twice、decades…）、**无大写专名** |
| v1.1 §4.2 粒度 | 每条 1–3 个标签、至少两条 ≥2 个、每事件 6–11 个、每个标签只属于一条事实、必含 date/place/agent/quantity |
| v1.1 §4.2 日期拆分 | date 标签只能是年份（名含 Year）、英文月名（名含 Month）或 1–31 的日（名含 Day）；**Day 标签后必须紧跟 Month 标签** |
| v1.1 §4.2 值的形式 | **专名或数字**（含数字或大写开头）；不以冠词开头、无句号 |
| v1.1 §5 同类替换 | 真值与错值同形（同单位、同写法）；同事件内值不重复 |
| v1.2 §2.4 打乱后可读 | 事实 7–24 词、单句、f2–fn 无衔接词（also/this/then…）；值的单位不在标签后重复 |
| 种子 | 35–130 词，按词边界含全部真值、不含任何错值 |

全表：错值高于真值的比例在 40–60%（数字/年/月分别算）；future 占 40–60%；同领域无重复句式；agent/name 真值最多用于 2 个事件；地点真值最多 max(4, 行数/50) 次；f1 主体不重复。

另修 `build_pairs.py` 的冠词：按读音而非首字母（an 8m、an 11,000、a university）。试点 720 对是按旧规则组装的，未重组。

## 3. 生成方式

先后试过 Sonnet、Haiku 子代理写作。Haiku 放弃逐条写作，改用模板脚本批量填充，产出不可用（科学类 268 条事实只有 6 个句式），已移至 `p4v2/_haiku_attempt/`（不进仓库）。最终用 DeepSeek API（`deepseek-flash`），脚本 `p4v2/gen_events_ds.py`：

1. **槽位由脚本定**：每个领域先让模型列 50 个不同子题材，脚本再给每个槽位分配国家（30 国轮换）、时态（各半）、n（全表 260:140）与编号。模型不自选故事，杜绝模板化。
2. **一次调用写一个事件**：先写种子新闻再抽事实；须通过 `check()`、与其他事件的比对（句式、实体、主体）和错值方向，否则把问题回传，最多 4 次。
3. **错值方向由脚本指定**：每个 (事件, 标签) 一枚固定硬币决定错值高于还是低于真值，模型按此写错值，校验器核对。

## 4. 审计与修复（第二轮）

第一轮生成后按计划原文逐条审计，发现 296/400 个事件至少违反一条：日期未拆分 192 个（`9 April` 放在一个标签里，另有星期、季节、钟点）、事实里有未标签数词 107 个、值不是专名或数字 120 个、语义问题 14 个。原因是校验器和规则当时没有写这三条，模型得不到反馈；不是模型思考等级的问题。

另一个问题是我造成的：第一轮用"生成后按硬币交换真值与错值"来平衡方向，逐标签交换破坏了真值故事的自洽（E2063 定价 24 欧元却写"高于 27–31 欧元区间"；E2272 重新开放早于封闭）。已改为上面第 3 点的"指定方向"，不再交换。

修复：补齐校验器（见 §2）与规则，对 400 个事件逐个调用 DeepSeek（**medium 思考**，修改要保持事实之间与种子一致），输入为该事件的校验器问题与复核意见，要求保留故事、主体、国家、时态与事实条数，真值构成一个自洽的故事，种子按真值重写。复核后再定点修 2 个（E2085 "the company" 指代不明；E2133 人物角色与种子矛盾）。

DeepSeek 复核（关闭思考、温度 0）修复后标记 21 个事件，逐条核对：2 个属实并已修；16 个是"大学/医院/法院不是 agent"之类误报（机构按定义属于 agent）；其余为标签名与值的单位不一致（`<Days>`=`60 hours`，标签名不进训练文本）。每领域随机抽读 1 个事件并填入真值与错值，均为可信新闻、语法通顺。

API 共调用 1,780 次、约 990 万 token，其中修复 804 次、约 660 万 token（含推理）。第一次全量修复因网络异常在 127 个事件后中断且结果未落盘；之后改为逐事件写入 `repair_done.jsonl`、断点续跑。

## 6. 遗留（不影响标签，按计划接受）

1. **错值不要求合理**（U7）：日的错值与真值可差数倍、年份可差数百年；跨事实的错值与其他真值可能不一致（换了小说家却没换遗产机构）。Set C 的 dim2 = 0 用来纠正凭合理性判断的倾向。
2. **少数标签名与值不完全对应**（`<Days>` 存的是小时）。标签名只给生成模型看，填值后不出现。
3. 种子里 9 处 "the" 后接专名。种子不进训练。
