# 多写手训练：E1 报告

**结论：** 用 4 个写手训练后，模型在没见过的写手 DeepSeek 上明显超过 token 级基线（dim1 0.725 对 0.643，领先 +0.081，95% CI [+0.049, +0.113]），5 个种子全部领先。但相比只用 Qwen 训练的 V1，总体提升不显著（+0.025 [-0.019, +0.070]），在 Qwen 上的分数还下降了。显著的改善出现在 Set B：V1 在 DeepSeek 的 Set B 上显著输给基线，多写手把差距收回到不显著。

## 实验设置

| 角色 | 写手 | 用途 |
|---|---|---|
| 训练 | Qwen3.8-27B、gpt-oss-20b、GLM-4.7-Flash、Gemma-4-26B | 每个写手写 70 个事件 |
| 开发 | Llama-3.1-8B | 选 epoch、校准阈值，不报告泛化分数 |
| 测试 | DeepSeek | 唯一没见过的写手，56 个事件 |
| 对照 | Qwen 留出（50 个事件）、v0 测试（60 个事件） | 写手已见过，事件没见过 |

- **方法：** 和 V1 相同，`train_pairce.py --rel --w-anti-b 0.3`，种子 42、1、2、3、4，只换了训练数据。
- **阈值：** dim1 阈值在 Llama 开发集上按 F1 选，dim2 阈值取 max(0.5, dim1 阈值)。5 种子集成的 dim1 阈值是 0.475。
- **基线：** 逐 token LR，用同一份多写手训练集重调（`baseline/`）。
- **显著性：** 按事件做 2000 次配对 bootstrap。

## 主要结果

dim1 F1：

| 测试集 | 基线 | 5 个种子 | 种子均值 | 5 种子集成 | 集成领先基线（95% CI） |
|---|---|---|---|---|---|
| **DeepSeek** | 0.643 | 0.744 / 0.727 / 0.694 / 0.729 / 0.725 | 0.724 | **0.725** | **+0.081 [+0.049, +0.113]** |
| Qwen 留出 | 0.657 | 0.734 / 0.751 / 0.734 / 0.737 / 0.751 | 0.741 | 0.742 | +0.085 [+0.050, +0.115] |
| v0 测试 | 0.617 | 0.704 / 0.731 / 0.710 / 0.710 / 0.730 | 0.717 | 0.745 | +0.128 [+0.100, +0.155] |

单种子在 DeepSeek 上的领先幅度为 +0.051 到 +0.100，各自的置信区间都不含 0。

dim2 F1（5 种子集成 / 基线）：DeepSeek 0.761 / 0.625，Qwen 留出 0.848 / 0.642，v0 测试 0.789 / 0.581。

## 和 V1 比较

V1 只用 Qwen 训练（3 种子集成）。差值是多写手减 V1，用同样的事件做配对 bootstrap。3 种子（42、1、2）一列用来和 V1 对齐种子数。

| 测试集 | V1 集成 | 多写手 5 种子 | 差值（95% CI） | 多写手 3 种子 | 差值（95% CI） |
|---|---|---|---|---|---|
| DeepSeek | 0.700 | 0.725 | +0.025 [-0.019, +0.070] | 0.736 | +0.036 [-0.013, +0.081] |
| Qwen 留出 | 0.789 | 0.742 | -0.047 [-0.081, -0.010] | 0.741 | -0.047 [-0.079, -0.016] |
| v0 测试 | 0.762 | 0.745 | -0.016 [-0.044, +0.013] | 0.722 | -0.040 [-0.070, -0.009] |

- **泛化差距缩小：** Qwen 留出与 DeepSeek 的差距从 0.089 降到 0.017。部分原因是 Qwen 分数下降，而不只是 DeepSeek 上升。
- **DeepSeek 上更稳：** 种子均值从 0.690 升到 0.724，最差种子的领先从 +0.031 升到 +0.051。两者种子数不同（3 和 5）。
- **Qwen 分数下降符合预期：** Qwen 的训练事件从 280 个减到 70 个。

## 按集合拆开

| 测试集 | 集合 | 模型 | 基线 | 领先基线（95% CI） | 相比 V1（95% CI） |
|---|---|---|---|---|---|
| DeepSeek | A | 0.783 | 0.606 | +0.178 [+0.111, +0.240] | -0.021 [-0.085, +0.046] |
| DeepSeek | B | 0.677 | 0.688 | -0.011 [-0.049, +0.022] | **+0.068 [+0.016, +0.122]** |
| Qwen 留出 | A | 0.854 | 0.617 | +0.238 [+0.191, +0.286] | -0.049 [-0.099, +0.003] |
| Qwen 留出 | B | 0.641 | 0.704 | **-0.062 [-0.112, -0.018]** | -0.052 [-0.099, -0.004] |
| v0 测试 | A | 0.838 | 0.591 | +0.247 [+0.201, +0.293] | -0.037 [-0.087, +0.019] |
| v0 测试 | B | 0.671 | 0.648 | +0.022 [-0.001, +0.049] | -0.004 [-0.036, +0.027] |

- **Set A：** 领先基线的部分几乎全部来自这里。
- **Set B：** 模型没有显著超过基线，在 Qwen 留出上还显著落后。A 和 Bf 的方向分不出来，两边都报时精确率约 0.55，F1 被压在这个水平。
- **多写手的实际收益：** V1 在 DeepSeek 的 Set B 上显著输给基线（-0.082 [-0.140, -0.024]），召回只有 0.698；多写手的召回升到 0.872，差距也不再显著。
- **Set C：** 模型和基线的误报都是 0 个 token。这个集合太容易，比较不出系统的好坏。

## 已知的局限

1. **未见写手只有一个：** 泛化结论全部压在 DeepSeek 这一个模型家族上。
2. **传抄对都是同写手：** 为了不写代码，这一轮按事件分配写手，同一事件的 A 和 B 总是同一写手，而真实转载通常跨媒体。
3. **训练集有文风线索：** Set A 全是单写手，而 Set B 有 75%、Set C 有 93% 的池子混了不同写手。开发集和测试集都是单写手。Set C 上没有出现误报，但 Set B 的干扰文档还没有单独检查。
4. **开发集偏小，且偏向短文档：** Llama 生成了 60 个事件中的 409 篇（满额 480 篇），填值后又有 122 篇超过 160 token 被丢弃，最后只剩 44 个事件。其他写手的丢弃：gpt-oss 11 篇，Qwen 3 篇，GLM 和 Gemma 为 0。
5. **阈值贴近断崖：** 集成在 DeepSeek 上 F1 随阈值的变化如下。阈值只比最高分低 0.012，但再往上就快速下跌。Qwen 留出和 v0 测试上也有类似的下跌，原因还没有验证，可能是方向惩罚把 Set B 的分数压在了 0.5 附近。

   | 阈值 | 0.40 | 0.45 | 0.475 | 0.50 | 0.525 | 0.55 |
   |---|---|---|---|---|---|---|
   | F1 | 0.737 | 0.731 | 0.725 | 0.688 | 0.600 | 0.524 |

6. **集成没有明显增益：** DeepSeek 上 5 种子集成（0.725）和种子均值（0.724）几乎相同，5 种子还低于其中 3 个种子的集成（0.736）。
7. **指标是有向的：** 下游计算独立来源数时用无向图，所以当前的有向 F1 可能低估 Set B 的实用价值。无向指标还没有算。

## 文件

- `README.md`：本报告。
- `runs/s*/`：每个种子的 `summary_seed*.json` 和 `train_seed*.jsonl`。
- `comparisons/`：`mw5` 和 `mw3` 是 `eval_ensemble.py` 的输出（单种子、集成、与基线比较）；`compare_*.txt` 是 `compare_mw.py` 的输出（与 V1 比较、按集合拆开、阈值扫描）。
- `predictions/{mw5,mw3}/`：集成的逐 token 推理结果，格式与 `results_v1/predictions/` 相同。
- `baseline/`：重调后的基线结果和逐 token 预测。
- `logs/`：生成和训练日志。`gen.log` 里的 `BUILD rc=1` 是默认 tokenizer 路径不存在造成的，之后手动加 `--tok` 重跑了构建。
- `writer_pilot/`：写手试点的文档和日志，包括失败的写手。
- `scripts/`：`gen_mw.sh` 生成数据，`serve.sh` 启动模型服务，`train_mw.sh` 训练。
- `../mw_train/`：多写手原始文档和 `pairs/` 数据集。
- 检查点每个约 450 MB，不进仓库，位于 `/mnt/hdd4/dujddx/tagged_pairce_mw_antib0.3_s{42,1,2,3,4}_20261104/best.pt`。

各处 bootstrap 的随机数不同，同一差值的置信区间边界可能相差约 0.004。个别 F1 在不同文件里末位差 0.001（如 v0 测试 0.745 和 0.746、Qwen 留出的 V1 0.788 和 0.789），是舍入造成的。

## 复现

```bash
bash results_mw/scripts/gen_mw.sh
bash results_mw/scripts/train_mw.sh 1 42 1 3
bash results_mw/scripts/train_mw.sh 2 2 4
python baseline_token.py --train mw_train/pairs --sets p4_pairs heldout/qwen_pairs heldout/ds_pairs --versions lr \
    --out results_mw/baseline/baseline_token.json --dump results_mw/baseline
python eval_ensemble.py --ckpts <5 个 best.pt> --val-data mw_train/pairs --sets p4_pairs heldout/qwen_pairs heldout/ds_pairs \
    --baseline results_mw/baseline/lr_tuned_on_train_for_f1 \
    --out results_mw/comparisons/mw5.json --dump results_mw/predictions/mw5
python compare_mw.py mw5 > results_mw/comparisons/compare_mw5.txt
```
